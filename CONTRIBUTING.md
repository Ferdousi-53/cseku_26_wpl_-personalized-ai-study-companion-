# Contributing Guidelines

## 1. Branching

Each feature or task should be developed in a separate branch.

Example:

feature/login
feature/rag
feature/study-planner
feature/pyq-analysis

## 2. Commit Messages

Use clear and meaningful commit messages.

Examples:

feat: add login screen
feat: implement document upload
feat: add vector search
fix: resolve authentication issue
test: add study planner tests

## 3. Pull Requests

Before merging code:

1. Create a Pull Request.
2. Describe the changes.
3. Review the code.
4. Run relevant tests.
5. Get approval from the other team member.
6. Merge the Pull Request.

## 4. Code Review

Both team members should review important changes before merging them into the main branch.

## 5. AI-Assisted Development

AI tools may be used for:

- Requirement analysis
- Code generation
- Test generation
- Debugging
- Documentation

AI-generated code must be reviewed, tested, and understood by the responsible team member before being merged.

## 6. Documentation

Important architectural, API, and implementation decisions should be documented in the repository.
